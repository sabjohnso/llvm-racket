* Correctness

All FFI signatures match the LLVM C API.  No bugs detected.

* GC / Lifecycle

** What's correct

All constants are properly anchored:

- Scalar constants (~Const-Int~, ~Const-Real~, ~Const-Null~,
  ~Const-All-Ones~, ~Get-Undef~): anchored to type (arg 0) ✓
- ~Const-String-In-Context~: anchored to context (arg 0) ✓
- ~Const-Array~, ~Const-Named-Struct~: anchored to type (arg 0) ✓
- ~Const-Struct~: anchored to first value element (arg 0) ✓
- ~Const-GEP2~: anchored to type (arg 0) ✓
- ~Const-Bit-Cast~, ~Const-Int-To-Ptr~, ~Const-Ptr-To-Int~: anchored
  to dest type (arg 1) ✓
- ~LLVM-Add-Global~: anchored to module (arg 0) ✓

** DONE [#A] LLVM-Const-String removed
CLOSED: [2026-03-21]

Removed the deprecated ~LLVMConstString~ binding which used the implicit
global context with no GC anchor.  Users should use
~LLVM-Const-String-In-Context~ instead.

** DONE [#A] LLVM-Const-Struct anchored
CLOSED: [2026-03-21]

Added ~(prevent-gc-wrap 0)~ to anchor the result to the first value
element in the list, transitively keeping the context alive.
